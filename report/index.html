🧊 AI 冰箱管家 + 剩菜改造师

专项方案报告

基于多模态大模型与保质期规则引擎，面向家庭食材管理、剩菜改造与浪费减少等场景，提供拍照识别、保质期管理、菜谱生成与浪费统计四大核心功能。各模块围绕用户需求、业务流程、系统架构、技术接入、数据资料、实施计划和验收标准展开。

技术栈：Streamlit + 智谱GLM-4V/GLM-4-Flash + JSON · 部署：Streamlit社区云 / serveo.net · 测试：105 passed · 覆盖率99.3%

01平台与建设思路

通用版提供拍照上传、大模型多模态识别（GLM-4V）、文本生成（GLM-4-Flash）、保质期规则引擎、JSON本地存储与统计看板。专项建设通过食材分类匹配、保质期计算、菜谱Prompt构造与证据表达规则，将这些能力组织为面向家庭食材管理的使用流程。

用户拍照或手动输入食材并确认数量、购买日期与存放位置，系统自动匹配食材类别并估算保质期，生成时间线分组展示；用户选择现有食材并填写口味偏好，AI生成含步骤、用时、难度与额外采购清单的菜谱；消耗与过期记录自动汇总为浪费统计看板。

完整闭环：拍照 → 识别食材 → 确认入库 → 保质期时间线 → 选食材+偏好 → AI生成菜谱 → 消耗/过期记录 → 浪费统计看板

03共享架构与业务链路

交互层

Streamlit四标签页：拍照识别、冰箱管理、今天吃什么、浪费统计。用户上传照片后确认识别结果并批量入库；冰箱管理以时间线分组展示食材状态（已过期/即将过期/建议冷冻/仍可存放），支持手动添加、消耗与删除；今天吃什么页面选择食材与偏好后生成菜谱卡片；浪费统计展示本周指标与环保反馈。

AI与工具层

拍照识别通过GLM-4V多模态大模型，图片转base64后发送识别Prompt，返回JSON格式的食材列表（名称、数量、存放位置）。菜谱生成通过GLM-4-Flash，构造包含现有食材与用户偏好的Prompt，返回JSON格式的菜谱（菜名、步骤、用时、难度、热量、份量、额外采购清单）。识别与生成结果均带用户确认环节，失败时降级处理不中断流程。

数据与规则层

食材数据存储在JSON文件中，包含食材信息、消耗记录与过期日志。保质期规则表定义10类常见食材（叶菜类、根茎类、瓜果类、蛋奶类、肉类、水产类、主食类、熟食类、干货类、水果类）的冷藏/冷冻/常温保质期天数与存储建议。开封食材保质期减半，未匹配类别兜底为3天。

运行部署

Streamlit单体应用，本地运行仅需 streamlit run streamlit_app.py 一条命令。API Key通过.env文件或Streamlit secrets管理。部署到Streamlit社区云后获得永久公开链接，公网访问也可通过serveo.net SSH隧道临时暴露。单元测试覆盖5个核心模块，105个测试用例，覆盖率99.3%。
